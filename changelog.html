1.49.2 - 20.11.2026

Исправлено

  • Падение Python-хелпера понятным текстом (пункт плана работ по аудиту, ошибка из App Store «Скачивание завершилось с кодом 6»). Выход по сигналу больше не выдаётся за код выхода: ChildProcess отличает сигнал (Output.signaled). Вместо трейсбека и «ответ не разобрался (0 байт, код 1)» человек видит причину на языке интерфейса: не хватило памяти (MemoryError, Metal out of memory, снят системой по SIGKILL), на диске нет места, модель не скачана, встроенный Python не запустился (ModuleNotFoundError, dyld, хелпер не стартовал) - «переустанови Surnia», иначе «аварийно завершился (сигнал N)» или «завершился с ошибкой (код N)». Код, сигнал, размер ответа и хвост stderr уходят в журнал (Хелпер). Так же разбираются скачивание моделей, проверка модели и ошибки, которые хелпер прислал сам. Таймаут - «помощник Surnia не ответил за N мин и остановлен», хвост stderr только в журнале. Нехватка памяти по-прежнему повторяется очередью сама.
  • Журнал облака без двойного префикса: было «облако: модель не ответила: адрес не отвечает…», стало «облако: адрес не отвечает…» (CloudSummary.reason/logLine). Тот же разбор у причины в заметке и у «Последней ошибки» после «Пересказать заново».
  • После удачного «Пересказать заново» заметка, сделанная при сбое облака, получает название из ответа модели вместо запасного «Встреча» - как в обычном конвейере (NoteRetitle). Только если в шапке был summary_failed и название в имени - «Встреча» (название человека и импорта не трогается). Имя и коллизии - как при создании («(1)»). Вместе с заметкой переименовываются запись и папка кадров (ссылка на кадры в заметке правится), в библиотеке голосов - путь заметки, путь записи и тема. Ссылки [[...]] из других заметок не правятся: на заметку со сбоем их не ставили. Путь заметки в status.json «Входящих» обновляется (Inbox.renameNote), CLI resummarize отдаёт новый путь. Известный риск: если человек сам назвал встречу ровно «Встреча», после повторного пересказа она тоже получит название модели - отдельного признака «название по умолчанию» в шапке заметки нет.

Новое

  • Окно контекста облака в карточке облака (вкладка «Модели»): поле «Окно контекста, токенов» (настройка cloud_num_ctx, по умолчанию 128000) с подсказкой; принимается число от 8000 до 2000000 (пробелы между цифрами можно), иначе в поле прежнее значение и подсказка с пределами.

1.49.0 - 19.11.2026

Папка «Входящие» и MCP для ИИ-агентов, спека docs/specs/2026-11-19-inbox-mcp-design.md, подробности для пользователя - docs/mcp.md.

Новое

  • Папка «Входящие» рядом с записями встреч (<папка записей>/Входящие): аудио и видео, положенные туда, Surnia разбирает сама, по одному файлу и только когда Mac свободен (нет встречи, записи, обработки и очереди - живые встречи всегда вперёд). Файл переезжает в «В работе», принимается как при «Разобрать запись…» (дата, время и название из метаданных и имени файла), идёт обычной очередью обработки, по готовности заметки уезжает в «Готово»; ошибка приёма или окончательный провал обработки - в «Ошибки» с причиной. Берутся файлы поддерживаемых форматов, размер которых не менялся 10 с, без скрытых и недокачанных (.part, .download); старые по дате изменения первыми; занятое имя - суффикс « (2)». После перезапуска разбор продолжается с того места. Статус - Входящие/status.json (атомарная запись, хранится 30 дней).
  • Настройка «Разбирать папку «Входящие»» на вкладке «Запись» (по умолчанию включена), путь к папке и кнопка «Открыть»; в меню во время разбора - строка «Входящие: 3 из 50».
  • MCP-сервер surnia-mcp для ИИ-агентов (Claude Code, Codex): программа внутри приложения (Contents/MacOS/surnia-mcp), stdio, JSON-RPC 2.0. Команды: submit_files (копирует файлы во «Входящие»; по каждому файлу - принят, нет доступа с путём «Входящих», не поддерживается, не найден), inbox_status (сколько ждёт / в работе / готово / с ошибкой, последние файлы с заметками и причинами ошибок), get_note (пересказ и задачи, расшифровка - только по флагу), recent_meetings (последние заметки: дата, название, путь). Программа работает в песочнице и передаёт команды запущенной Surnia через сокет в контейнере группы приложений 57Y7Q2X446.com.wolk88.surnia; Surnia не запущена - ошибка «Surnia не запущена - откройте приложение». Заметки читаются только из папки встреч Surnia.
  • «Входящие», надёжность (ревью 19.11.2026): встреча, начавшаяся во время приёма файла, идёт вперёд - запись «Входящих» встаёт в очередь на свободном такте, а в очереди встречи берутся раньше записей «Входящих»; файл считается докопированным по размеру и времени изменения, пустые, с соседним .part/.download/.crdownload и с «занятой» датой Finder не берутся, а файл, изменившийся во время приёма, принимается заново; временные сбои приёма (папка записей недоступна, wav не записался, ввод-вывод, облачный файл не скачан) повторяются через 1 и 10 минут, потом - «Ошибки»; после перезапуска без найденной заметки - «ошибка» «заметка не найдена, проверь вручную», а не ложное «готово»; запись, выпавшая из очереди, возвращается сама; неудачный перенос в «Готово»/«Ошибки» повторяется; неподдерживаемые файлы и ссылки в корне - в статусе «ошибка» без переноса; «Повторить обработку» для файла из «Ошибок» переводит его в «Готово». Разбор идёт своей очередью, медленная папка не задерживает детектор.
  • «Удалить данные» не стирает папку записей, если во «Входящих» есть файлы; скан архива голосов и поиск записей при переименовании голоса не заходят во «Входящие».
  • Блок «Агенты (MCP)» на вкладке «Основные»: путь к программе и кнопка «Скопировать» - настройка для Claude Code (mcpServers) в буфер обмена. В справке - как подключить, команды, пример задания для агента и что заметки уходят агенту только по его запросу.

Изменено по ревью MCP

  • Переключатель «Разрешить агентам (MCP)» в блоке «Агенты (MCP)», по умолчанию выключен (agents_enabled). Сервер поднимается только при включённом доступе и останавливается сразу при выключении; surnia-mcp при выключенном доступе отвечает «Доступ агентов выключен в настройках Surnia». Подпись: включённый доступ даёт любой программе учётной записи читать заметки встреч, аудиозаписи не уходят. Ошибка запуска сервера (например, слишком длинный путь сокета) - под переключателем.
  • Выход приложения не ждёт копирования: остановка ждёт обработчик не больше секунды, сокет удаляется сразу, копирование кусками прерывается между кусками и файлами; брошенная копия убирается при следующем запуске сервера.
  • submit_files: ссылки разворачиваются (копируется содержимое), не больше 100 путей за вызов, перед каждой копией - проверка места (размер файла и 1 ГБ запаса).
  • get_note: проверка папки встреч и «.md» - на настоящем пути и до проверки существования; ответ для отсутствующего и чужого файла один.
  • Общий срок 30 с на чтение запроса и на запись ответа: медленный клиент не держит канал.
  • Сборка без права на группу держит сокет в ~/Library/Application Support/Surnia-dev, а не заводит контейнер группы руками.

Исправлено

  • Тесты больше не трогают настоящие папки: «Входящие» в ~/Documents/Surnia/recordings создал шаг «Входящих» из теста рантайма, который пришёл уже после удаления временной папки теста и взял пути по умолчанию. Тест рантайма гасит рантаймы и ждёт их очередей до удаления папки, тесты с настройками держат записи, встречи и базу во временной папке, check.sh сверяет ещё и список папок в настоящей папке записей.

Новое

  • Одна папка «База знаний» на вкладке «Основные» вместо двух («Папка для отчётов о встречах» и «Папка словарей и настроек»), с подсказкой: если есть Obsidian, укажите папку своей базы. Встречи - подпапка базы (у кого папка встреч уже внутри базы - тот же путь). Записи - отдельно. Смена базы переносит только файлы Surnia: пять служебных заметок и папку встреч. Не начинается во время записи или обработки; выход из приложения дожидается конца переноса. Папка встреч не переносится целиком, если это общая папка (дом, Документы, Рабочий стол, Загрузки, облачные диски, тома, чужое хранилище Obsidian или репозиторий), записи и данные приложения из переноса исключены.
  • Разбор файла: дата и время встречи - из тегов метаданных, затем из имени файла (Zoom, запись экрана Mac, OBS, Диктофон, телефоны), затем время создания файла, затем дата файла; откуда взята дата - подпись в окне разбора. Только дата - заметка без времени («18.11.2026 0.25ч Название»). Название из метаданных подставляется в окно разбора.
  • Причёсывание расшифровки перед пересказом (вкладка «Модели», по умолчанию выключено): та же модель, что пересказ, расставляет пунктуацию и правит явные ошибки распознавания. Кусок остаётся исходным, если модель поменяла число строк, метки, длину, слова, числа или отрицания. Расшифровка в заметке не меняется, цитаты задач сверяются с исходной. Потолок 24 мин на шаг, время шага - в строке этапов журнала.
  • Gemma 4 31B в выборе моделей пересказа (от 36 ГБ памяти, не по умолчанию; Apache 2.0).

Исправлено
